# The BoSS website

Source for the website of **the BoSS**, the Benchmark of Stellarator Simulations.
It is built with [Sphinx](https://www.sphinx-doc.org/) and the
[sphinx-book-theme](https://sphinx-book-theme.readthedocs.io/) (the same theme and
settings as the [DeepHyper docs](https://deephyper.readthedocs.io), with a
simsopt-style left-only sidebar), with pages written
in Markdown ([MyST](https://myst-parser.readthedocs.io/)), and served at
https://boss.flatironinstitute.org/ from the Flatiron file system.

## Preview locally

Set up a virtual environment once. The package pages are generated from the
docstrings of `boss-bench`, so install it too, from a local checkout:

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
pip install -e /path/to/boss_bench
```

Then, with the environment active, build the site:

```bash
sphinx-build -b html docs docs/_build/html
```

and open `docs/_build/html/index.html`.

For live reload while editing: `pip install sphinx-autobuild` and run
`sphinx-autobuild docs docs/_build/html`.

Rebuild from scratch (`rm -rf docs/_build` first) before publishing. An
incremental build only rewrites the pages whose source changed, so the other
pages keep an old sidebar, deleted pages stay in the output, and edits to
`docs/_static/` alone are not copied.

## Layout

```text
docs/
  conf.py                Sphinx config: theme, header icons, extensions
  index.md               home page; its captioned toctrees ARE the left sidebar
  download.md, download-models.md, data-explorer.md
  tutorials/             exploring a stellarator, trajectory data, surrogate model
  _static/tutorials/     tutorial figures, generated by running the tutorial code on real files
  data/                  database overview, ideal MHD, fast-ion confinement
  _static/video/         video at the top of the home page, with its poster frame
  _static/overview/      histograms on the database overview (scripts/make_overview_figures.py)
  _static/custom.css     logo tile in dark mode, prev/next buttons, home-page video, stat tiles
  _static/logo/          stellarator image from the ARTEMISS logo
  _templates/            sidebar template (pages expand into their sections), GitHub link
                         with star and fork counts in the header (repo-stats.html)
icons/                   old ARTEMISS logo files (not used by the site)
legacy_mkdocs/           the previous MkDocs Material version, kept for reference
scripts/                 regenerate the database numbers and figures (see below)
```

To add a page, create the `.md` file and list it in the matching toctree at
the bottom of `docs/index.md`.

Cards, buttons, tabs and dropdowns come from
[sphinx-design](https://sphinx-design.readthedocs.io/); admonitions use MyST
`:::{note}` blocks; math is `$...$` and `$$...$$`.

## Database numbers and figures

The numbers on `docs/data/overview.md` and its histograms come from the release
files on the cluster. Refresh them when the database grows:

```bash
ssh rusty 'source ~/code/ml/env_ml_fast_ion/bin/activate; python -' < scripts/collect_stats.py
scp 'rusty:ceph/artemiss/web/boss_site_{stats.npz,files.json}' .
python scripts/make_overview_figures.py boss_site_stats.npz boss_site_files.json
```

The last command rewrites the histograms and prints the numbers quoted on the
page (counts per source, files, sizes), which are then updated by hand.

## Package documentation

The **Package documentation** section is an overview page, `docs/package.md`,
followed by one API page per module of the `boss-bench` package, generated at
build time from its Google-style docstrings and written to `docs/api/` (not
committed). The modules and their order are `API_MODULES` in `docs/conf.py`.
Submodules in `API_SUBMODULES` (the three `boss_bench.models` modules) get pages in
`docs/api/<module>/`, listed under their module's page in the sidebar. The
build stops with an error if the package can't be imported, so install it in the
build environment first (`pip install -e /path/to/boss-bench` while developing).
PyTorch and safetensors, which `boss_bench.models` needs, are mocked
(`autodoc_mock_imports`), so the build does not install them.

To build against a local checkout while developing the package:

```bash
BOSS_PACKAGE_SRC=/path/to/boss-bench .venv/bin/sphinx-build -b html docs docs/_build/html
```

The deploy workflow installs `boss-bench==1.0.0` from PyPI before building, so the
documentation always matches the release that accompanies the paper.

## Deploying

The Flatiron web server serves https://boss.flatironinstitute.org/ straight from
`docs/_build/html` of this checkout on the Flatiron file system, so publishing is
rebuilding that folder. Pull `main`, then, with the venv active, rebuild from scratch:

```bash
git pull
rm -rf docs/_build
sphinx-build -b html docs docs/_build/html
```

The package pages come from the `boss-bench` installed in the venv, so install the
released version, or set `BOSS_PACKAGE_SRC` to a checkout of the version to document.

GitHub Actions (`.github/workflows/build.yml`) builds the site on every push and pull
request with warnings as errors, as a check; it does not deploy.
